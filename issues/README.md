# Marketplace Issues & Seller Support Cases

A reference library for documenting marketplace problems, support cases, investigations, resolutions, and lessons learned. The goal is to make future cases faster to diagnose and resolve without repeating the same research.

## Folder & File Naming

- Group case records by marketplace (for example, `amazon`, `walmart`, or `tiktok-shop`).
- Name each case file with the marketplace's case ID when one exists: `<case-id>.md`.
- If there is no support case ID, use a short, descriptive filename and include the marketplace and issue in the document title.
- Keep separate cases separate, even when they relate to the same underlying issue. Cross-link related records when helpful.

## What to Capture

When available, document the following in each case file:

1. **Marketplace and issue** — affected platform, account/ASIN/SKU or listing, and a concise problem statement.
2. **Case details** — support case ID, opened/updated dates, case status, and the relevant support team's response.
3. **Evidence** — relevant screenshots, reports, error messages, or links to source records.
4. **Investigation** — checks performed, findings, confirmed root cause, and any unresolved questions.
5. **Resolution / Plan of Action** — actions taken, owner, dates, evidence submitted, and the marketplace's outcome.
6. **Prevention / lesson learned** — the process, monitoring, or documentation change that can help prevent recurrence.
7. **Next step** — the outstanding action and who owns it, if the issue remains open.

Not every case will have every field at the start. Record verified facts first and update the record as the case develops.

## Documentation Rules

- **Preserve the case ID exactly.** It is the primary reference for finding the support conversation again.
- **Keep a clear timeline.** Distinguish the date of a marketplace message from the date we took action.
- **Separate facts from assumptions.** Label unconfirmed causes and pending questions; do not present a theory as the root cause.
- **Keep source evidence traceable.** Link to the relevant Seller Center page, internal tracker, or approved document when accessible. Do not rely on an unsupported summary when the original evidence is available.
- **Record outcomes, not just messages.** A support reply is not a resolution unless the issue is actually cleared or the next required action is explicit.
- **Protect sensitive information.** Do not store passwords, access tokens, payment details, or unnecessary customer personal data here. Use approved, access-controlled locations for sensitive evidence.
- **Avoid duplicate documentation.** Keep the detailed investigation in one case file and link to it from trackers or related project documents.
- **Keep records useful and current.** Update open cases as they progress; retain closed cases as historical references without treating old guidance as automatically valid for a new case.

## Suggested Case Workflow

1. Create or update the marketplace-specific case file as soon as a meaningful support interaction occurs.
2. Save the exact case ID, message date, issue, and requested information.
3. Investigate the issue and collect the evidence needed to support the response.
4. Document the root cause only when supported; otherwise record the working hypothesis and what must be verified.
5. Track the Plan of Action, owner, due date, submission, and support outcome.
6. Once resolved, add the confirmed fix and prevention step so the next similar case can start from prior learning.

## Working Principle

**Capture the case once, preserve its evidence, and turn the resolution into reusable operational knowledge.**
